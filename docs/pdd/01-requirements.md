# 拼多多模块需求与业务流程

关联：[索引](00-overview.md)、[统计口径](06-metrics-and-quality.md)。

## 1. 使用场景与范围

运营希望在一个 ERP 工作区管理多个拼多多店铺，避免重复下载订单和手工拼表。商品人员维护一次 ERP 产品资料，再生成不同店铺的发布草稿。

| 业务 | 第一版交付 | 边界 |
| --- | --- | --- |
| 店铺接入 | 应用配置、绑定已有店铺、授权、过期提醒、能力展示 | 不保存商家后台密码，不复用浏览器 Cookie |
| 订单 | 列表/详情、状态、时间与金额、商品明细、增量及历史回补 | 隐私字段仅取必要授权范围，默认脱敏 |
| 售后 | 售后单、状态、成功退款金额、关联订单 | 不自动审核售后或发起退款 |
| 商品 | 远端商品/SKU、销售状态、价格和平台库存快照 | 平台库存与 ERP 实物库存分开 |
| 销售汇总 | 多店、日期、商品/SKU维度，支付、退款、净支付、排名 | 无数据的成本、广告、费用不显示为零 |
| 商品发布 | ERP 选品、多店草稿、类目/规格、素材、预检、提交、审核跟踪 | 有发布权限才可自动提交；未获权限走资料包流程 |
| 文件导入 | API 暂不可用或历史范围不足时导入官方导出文件 | 模板与金额口径先核验；不任意猜测字段 |

首版排除：广告/流量同步、利润和结算、采购/BOM、自动平台退款、自动改价、全店铺库存联动、平台自动发货、消息营销、未经授权数据采集。

## 2. 角色和权限

| 角色 | 能力 |
| --- | --- |
| 系统管理员 | 配置应用、绑定店铺、管理成员范围、查看任务和授权异常 |
| 运营负责人 | 查看授权店铺汇总、发起同步、审核商品草稿、逐店提交 |
| 商品编辑 | 从 ERP 选品、整理素材/类目/SKU、编辑获授权店铺草稿 |
| 分店运营 | 只访问被分配的店铺数据和任务 |
| 财务/管理查看者 | 获授权后读取经营汇总和导出，不默认取得商品发布权限 |

店铺 owner_name 当前是显示文本，不能直接作为登录员工授权依据。必须使用员工/用户稳定 ID 分配访问范围。新增 pdd 功能权限与店铺范围都满足后才能操作；查询、详情、汇总、导出、后台任务提交都校验，禁止仅由前端过滤。

## 3. 店铺接入流程

管理员创建或选择现有拼多多平台下的电商店铺 → 设置提供方 PDD → 发起官方授权 → 回调验证店铺真实 ID → 确认内部与外部店铺绑定 → 校验授权能力 → 小窗口同步 → 对账后开启周期同步。

- 平台目录编码由系统生成，不能假定平台编码固定为 pdd，不能根据名称推断类型。
- 一个外部店铺 ID 只能绑定一个内部 shop_id。名称不同或重名不影响身份校验。
- 授权到了别家店铺时拒绝自动覆盖；展示脱敏身份并让管理员重新选择或建立正确资料。
- 授权过期/撤销：暂停新远程任务，保留历史数据，页面提示重新授权。
- 停用店铺：暂停新同步及发布；历史仍按权限查询；运行中的远程结果继续核实。

## 4. 同步与阅读流程

选择店铺和数据类型 → 设置允许的时间范围 → 创建任务 → 展示队列与分店结果 → 查看订单/售后/商品 → 进入汇总看板。

多店任务拆成逐店子任务；一家店铺限流、权限缺失或失效不拖垮其他店。用户可以停止未发送的任务、对明确失败的窗口重试、发起补数。正在处理的页面请求被关闭不等于服务端任务取消。

订单详情展示时间、状态、金额、明细、对应售后、来源和数据更新时间。ERP 映射缺失时仍能查看远端业务数据，只标记「待映射」。

## 5. 商品映射

以 shop_id + 外部商品/SKU ID 定位，不根据标题或名称自动绑定。支持一个 ERP SKU 对应多个店铺的多个外部 SKU，每个外部 SKU 同时只能有一个有效 ERP SKU 映射。

运营可接收候选建议并人工确认；停用或缺失 SKU 显示异常。订单明细保留成交时的平台标题、规格、价格快照。映射变化不能改写既往订单事实；按 ERP 商品汇总标明映射版本与未映射金额。

首版只支持一对一单位对应的映射，不自动展开套装或换算包装单位。

## 6. 从 ERP 商品上链接

1. 选择 ERP 商品与目标店铺，读取版本化商品/SKU/图片快照。
2. 为每店生成独立草稿，设置标题、店铺类目、规格、主图/详情图、价格、发布数量、运费模板及经营资质。
3. 选择官方返回的末级类目，加载当前必填属性、规格规则和资质要求；ERP 分类不直接作为平台类目 ID。
4. 分店预检并展示差异：价格、库存、图片、类目和缺失资质；未通过的店铺不提交。
5. 用户确认逐店内容，提交可发布草稿，生成逐店任务。明确提示此动作会创建真实平台商品。
6. 跟踪平台提交受理、审核中、审核拒绝、上架/未上架状态；取得实际外部商品 ID 后回读。
7. 平台已返回可验证链接时显示「打开商品链接」；不能取得链接时只显示商品 ID 与「前往商家后台」，不拼接未经确认的 URL。

单买价、团购价、划线价、库存上限等只是待核验字段类别；仅在已确认官方接口确实支持时启用对应字段和规则。不能假设 ERP defaultSalePrice 就等于任一平台售价。

## 7. 发布任务状态

| 层次 | 状态 | 含义 |
| --- | --- | --- |
| 草稿 | draft / ready / frozen | 编辑中、预检通过、提交内容已冻结 |
| 本地任务 | queued / sending / awaiting_result / unknown / succeeded / failed / cancelled | 排队、发出、等待结果、结果不确定、已确认成功、明确失败、发送前取消 |
| 平台商品 | remote_status + normalized_status | 原始状态保留，规范状态可为 reviewing / rejected / listed / unlisted / unknown |

succeeded 表示已确认平台接受且绑定外部商品记录，不表示已审核通过或已上架。页面分别显示「提交结果」和「平台状态」。明确拒绝可以修订生成新版本；超时、断连、进程崩溃后的 unknown 必须先查询和核实，不自动再次创建商品。

同商品同店默认阻止重复创建。已有链接需走单独的更新功能（后续范围）；确需另建链接只能明确选择「新建另一链接」、填写原因、授权并核验前次结果。

## 8. 平台库存策略

多店共享同一实物库存时，每店不能默认发布 ERP 全部余额。首版发布数量由运营逐店分配；展示多个待发布任务的数量合计及 ERP 可参考余额。

目前没有统一的电商库存预占/分配系统。页面提示「发布数量不代表 ERP 库存预占；需考虑线下销售与其他平台」。后端校验非负整数及已核验的平台上限，不承诺跨渠道防超卖。自动库存分配和同步回写须另行设计再上线。

## 9. 用户可见的异常与完成标准

授权失效显示重新授权入口；能力不足显示具体缺失能力；同步失败显示店铺、数据类型和窗口；汇总显示完整/部分/待核验状态；发布结果不确定显示「核实中，请勿重复提交」。

首批验收：至少两家店铺可独立授权和同步，订单与退款核对成功，汇总无重复，一家店的单商品发布闭环通过，多店任务部分失败可恢复且不重复创建商品。
