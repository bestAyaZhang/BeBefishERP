## 1. 本轮确认的目标

在 BeBefish ERP 内接入多个自有或合法授权的拼多多店铺，拉取订单、售后、商品，跨店汇总销售数据，并从 ERP 商品资料生成拼多多商品发布任务。「上链接」在本文中指创建拼多多商品并跟踪审核、上架和链接状态，不包含推广链接或多多进宝选品。

第一版包含申请与授权流程。暂不纳入广告消耗、流量分析、结算对账、完整利润、自动库存回写或自动平台发货。若官方应用资质或接口权限不支持某项能力，页面明确说明限制；数据读取可使用官方导出文件导入，发布可生成资料包并到商家后台人工完成，不展示虚假的同步或发布成功。

## 2. 推荐实施顺序

1. 申请应用、核验读取及商品发布权限，先用一家店铺走通授权。
2. 建立多店绑定、授权状态、店铺数据权限和任务中心。
3. 同步订单、售后、商品，并核对销售汇总口径。
4. 建立外部商品/SKU 与 ERP 商品/SKU 的映射。
5. 完成一个商品在一家店铺的草稿、校验、提交、结果核实。
6. 扩展同一商品向多店发布、异常恢复与小范围试运行。

不要同时把多店同步、财务记账、自动扣库存和自动上架绑定为一个大任务。

## 4. 与现有项目的衔接

| 现有能力 | 本模块做法 |
| --- | --- |
| 平台与店铺目录：sales_platform、platform_shop | 复用 shop_id；新增提供方绑定、授权、能力记录，不再建一套店铺主数据 |
| ERP 商品与 SKU、图片和包装 | 读取商品快照形成发布草稿；各店标题、价格、类目和承诺可分别设置 |
| 认证、sys_permission、角色 | 新增 pdd 权限，同时建立后台校验的店铺访问范围 |
| 库存、销售单、发货与安能 | 首版不自动扣库存、不生成线下销售单、不发送平台发货；后续设计独立转换和防重复规则 |
| Vue features、services/http.ts | 新增 features/pdd，复用统一响应、分页、登录过期与权限处理 |
| Java 21、Spring Boot、MySQL 8 | 新增 com.bebefish.erp.pdd，按 api/application/domain/infrastructure 分层 |
| 已有 V1–V26 迁移 | 从实施时最新空闲版本开始追加，不修改已执行迁移 |
| Redis 在早期架构文档中为计划项 | 首版任务队列、租约与游标使用 MySQL，不新增强制 Redis 依赖 |

旧阶段计划和数据库文档部分描述落后于实际代码。本套方案以当前代码为衔接依据；不会沿用内存认证、短信登录或尚未安装的组件作为前提。

## 5. 决策与待核验项

已确定：多店、订单/售后/商品/销售汇总、商品发布，包含申请授权流程，模块化单体，首版无自动库存回写。

接入前须确认：应用类型与资质；是否允许这些店铺授权；官方提供的每项读取/发布能力；接口字段、时间窗口、限流、历史可追溯范围；商品类目与资质要求；是否有测试环境；审核结果及真实链接的获取方法。核验结果记录到 02 文档的能力矩阵，不凭经验填入接口名或额度。

业务试运行前须确认：首批店铺及负责人、导入历史范围、统计支付金额是否含运费、初期发布类目、平台库存人工分配策略。默认历史回补申请最近 30 天，范围仍须符合实际接口权限。

## 6. 文档使用边界

这是一套待实施设计，不会立即调用外部 API、写入经营数据或发布真实商品。官方公开页面于 2026-10-12 可访问，但只获取到动态网页外壳，尚未核验具体接口目录、参数或应用资格。所有远程接口名称、权限和限制须由实际应用控制台确认；不得把本文中的内部 API 路径当成拼多多官方接口。
