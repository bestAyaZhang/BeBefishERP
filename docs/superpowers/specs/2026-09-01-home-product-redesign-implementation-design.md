# BeBefish ERP 首页与商品管理改版实施设计

日期：2026-09-01

## 1. 背景与目标

本轮将已经确认的 Figma 原型落到现有前后端工程中，优先完成两部分：

1. 改造 ERP 主框架与工作台首页，使页面使用通栏桌面布局，并基于真实业务数据展示销售、订单、库存、商品和供应商概况。
2. 完整改造商品管理模块，打通分类筛选、商品列表、独立详情页、六步新增/编辑向导、SKU 维护、采购报价、包装重量和图片上传。

本轮不是纯静态原型。人工维护的商品资料需要保存到数据库；库存、资料完整度和首页统计等可计算数据由现有业务表实时聚合，不重复存储。

## 2. 已确认的产品决策

- 采用按业务模块拆分、前后端纵向打通的实现方式，不继续扩充现有巨型原型组件。
- 主框架占满浏览器宽度，左侧导航固定约 `244px`，不保留外围大面积空白。
- 商品列表左侧为分类树，右侧为商品表格；分类树只负责筛选，分类修改和删除只在分类管理模块进行。
- 商品查询条件只保留“货号 / SKU”，支持回车查询、重置和服务端分页。
- 表格不使用竖向分隔线，操作列使用文字“查看详情”。
- 商品详情使用独立只读页面，不使用右侧抽屉；右上角提供“编辑商品”。
- 新增和编辑商品使用六步向导。
- SKU 支持新增和单独维护；包装重量支持“全部 SKU 统一”和“按 SKU 单独维护”。
- 商品图、SKU 图、外箱图和内盒包装图使用图片上传组件。
- 渠道售价不是本轮稳定业务信息，不保存到数据库，也不作为详情页固定字段。
- 采购信息继续使用现有供应商报价模型。
- 商品详情不展示附件资料，也不展示原型中已取消的商品描述、销售属性和合规资料区块。
- 审计区只展示系统能够可靠提供的创建时间、更新时间和状态；历史操作人没有可靠数据来源时不伪造姓名。

## 3. 范围

### 3.1 本轮包含

- 全屏应用框架、侧边栏和顶部工具栏改造。
- 工作台首页及聚合统计接口。
- 商品分类树筛选、商品列表、分页和状态展示。
- 商品只读详情页。
- 商品新增、编辑六步向导。
- SKU 新增、编辑和图片维护。
- 供应商采购报价维护。
- SKU 安全库存、包装尺寸、内盒尺寸、重量和包装图片维护。
- 数据库增量迁移、后端校验、事务和前端接口映射。
- 加载、空数据、错误、上传和未保存离开提示。
- 前后端自动化测试、构建与真实接口联调。

### 3.2 本轮不包含

- 渠道销售价表、渠道售价维护和渠道利润分析。
- 分类管理模块的重新设计；商品页只消费现有分类数据。
- 客户、供应商、仓库、销售和库存业务页面的整体视觉重构。
- 附件资料、合规资料和商品营销文案维护。
- 移动端专用界面；本轮以桌面 ERP 为目标。
- 为缺失业务数据填充演示数字。

## 4. 总体架构

### 4.1 前端结构

保留 Vue 3、TypeScript、Vue Router、Tailwind、Lucide 和现有服务层，不新增状态管理框架。页面状态由路由页面、组合式函数和服务模块管理。

前端按以下边界拆分：

- `layout`：全屏框架、侧边栏、顶部工具栏和面包屑。
- `workbench`：统计卡片、趋势图、库存提醒和快捷入口。
- `product/list`：分类树、货号搜索、表格和分页。
- `product/detail`：商品概览、SKU、采购、包装图片和审计区。
- `product/editor`：六步向导、步骤校验、草稿状态和最终提交。
- `product/sku`：SKU 编辑宽弹窗和规格组合处理。
- `product/packaging`：统一包装表单、逐 SKU 包装表格和维护宽弹窗。
- `shared`：统一输入框、下拉框、图片上传、状态标签、空态和反馈组件。

现有 `WorkspacePrototype.vue` 不再作为生产路由入口。可复用的视觉片段拆出后，由新的专用页面和组件接管；不进行与本轮无关的全局重构。

### 4.2 后端结构

后端沿用 Spring Boot、分层领域结构、JdbcTemplate/JPA 混合持久层和 Flyway。新增能力按现有模块边界放置：

- 商品字段、详情聚合和保存事务放在 `product` 模块。
- 库存数量和预警计算从 `inventory_balance` 聚合。
- 首页销售与订单趋势从 `sales_order` 及订单明细聚合。
- 商品、SKU 和供应商数量从现有主数据表聚合。
- 首页只提供查询接口，不写入统计快照表。

## 5. 路由与页面

### 5.1 应用框架

- 左侧导航宽度约 `244px`，固定在视口左侧并贯穿全高。
- 顶部工具栏从侧边栏右侧开始铺满剩余区域，高度约 `64px`。
- 主内容区不设置 `1440px` 外层最大宽度，使用 `24px` 左右内边距。
- 宽屏充分利用空间；较窄桌面允许表格区域横向滚动，但标题、工具栏和分页不被遮挡。

### 5.2 路由

- `/workbench`：新版工作台首页。
- `/products`：分类树和商品列表。
- `/products/new`：新增商品六步向导。
- `/products/:id`：商品只读详情。
- `/products/:id/edit`：编辑商品六步向导。

SKU 和包装维护采用页面内宽弹窗，不增加可直接访问的子路由。这样可以保留向导上下文、未保存状态和当前步骤，同时避免用户在维护单个 SKU 时丢失整单录入内容。

### 5.3 工作台首页

首页只展示现有数据能够支持的指标：

- 商品总数、启用商品数、SKU 总数、启用供应商数。
- 库存为零 SKU 数和低于或等于安全库存的 SKU 数。
- 当前周期订单数、销售额、未收金额和草稿订单数。
- 按日期聚合的销售额与订单数趋势。
- 库存风险商品摘要和最近订单摘要。

不展示当前数据库无法支持的待发货、待售后、待评价、投诉和违规商品等电商平台指标。

### 5.4 商品列表

- 左栏展示分类搜索和树状分类，包含“全部商品”入口及各节点商品数量。
- 选择父分类时包含所有后代分类的商品；选择叶子分类只筛选该分类。
- 右栏顶部合并标题、货号/SKU 查询、搜索、重置和新增商品操作。
- 表格展示商品图片、商品名称与货号、分类、品牌与默认供应商、库存、价格、资料状态、业务状态和操作。
- 库存是该商品全部 SKU、全部仓库余额之和。
- 价格优先展示默认 SKU 售价；没有可用价格时显示 `--`。
- 分页由服务端执行，切换分类或查询条件后回到第一页。
- 行点击与“查看详情”均进入独立详情页。本轮没有已确认的批量业务，因此列表不展示复选框和批量操作按钮。

### 5.5 商品详情

详情页为只读布局，包含：

1. 商品概览：商品图、商品编码、货号、名称、分类、品牌、类型、状态和备注。
2. SKU 明细：SKU 图片、SKU 货号、规格、条码、销售单位、售价、成本、当前库存、安全库存和状态。
3. 采购信息：按 SKU 展示供应商、供应商货号、采购价、起订量、默认报价和状态。
4. 包装与重量：根据各 SKU 数据自动判断为统一展示或逐 SKU 表格，展示外箱尺寸、内盒尺寸、装箱数量、包装方式、克重、净重、毛重和内盒重量。
5. 图片资料：商品图、SKU 图、外箱图和内盒包装图。
6. 审计信息：创建时间、更新时间和当前状态。

右上角只提供“编辑商品”主操作。详情区不支持原地编辑。

### 5.6 六步商品向导

步骤固定为：

1. 基本信息：货号、商品名称、分类、品牌、商品类型、状态和备注。
2. SKU 信息：规格定义、SKU 组合、SKU 货号、条码、名称、单位、售价、成本、安全库存、SKU 图片和状态。
3. 采购信息：SKU、供应商、供应商货号、采购价、起订量、默认报价和状态。
4. 包装与重量：统一模式或逐 SKU 模式，维护包装尺寸、重量、数量和包装图片。
5. 图片资料：商品主图、SKU 图、外箱图和内盒包装图；已在 SKU/包装步骤上传的图片在此汇总检查。
6. 确认提交：按分区只读预览、缺失项提示和最终保存。

每一步只校验进入下一步所需的字段；最终提交执行完整校验。编辑页面复用同一向导并预填现有详情数据。

## 6. 数据模型与数据库迁移

### 6.1 复用现有字段

- 商品：`product_code`、`item_no`、`product_name`、`category_id`、`brand`、`product_type`、`main_image_file_id`、`status`、`remark`。
- SKU：`sku_code`、`barcode`、`sku_name`、规格、销售单位、售价、成本、SKU 图片和状态。
- 外箱与重量：现有 `package_length_cm`、`package_width_cm`、`package_height_cm`、`package_volume_cm3`、`net_weight_kg`、`gross_weight_kg`、`gram_weight_g`、`packaging_method`、`carton_quantity`、`package_image_file_id`、`carton_image_file_id`。
- 采购：现有 `sku_supplier_quote` 表。
- 审计：现有 `created_at`、`updated_at` 和状态字段。

现有 `barcode` 在界面中命名为“单杯条码/条码”，现有 `default_sale_price` 在界面中命名为“单价”。现有包装长宽高明确解释为外箱尺寸。

### 6.2 新增 SKU 字段

通过下一条 Flyway 增量迁移给 `product_sku` 增加：

- `safety_stock_quantity decimal(18,4) not null default 0`
- `inner_package_length_cm decimal(12,3) null`
- `inner_package_width_cm decimal(12,3) null`
- `inner_package_height_cm decimal(12,3) null`
- `inner_package_weight_kg decimal(12,3) null`

所有新增数值字段增加非负约束。历史 SKU 的安全库存默认 `0`，其他新增字段保持空值，不猜测历史包装数据。

### 6.3 包装模式

数据库不保存单独的“统一/逐 SKU”模式字段，包装数据始终存放在每个 SKU 上：

- 统一模式提交时，将同一组包装字段复制到当前商品的全部 SKU。
- 逐 SKU 模式提交时，分别保存每个 SKU 的包装字段。
- 编辑时，如果全部 SKU 的包装字段完全一致，界面默认识别为统一模式；否则识别为逐 SKU 模式。
- 从逐 SKU 切回统一模式时，界面明确提示统一值会覆盖 SKU 差异，用户确认后才应用。

### 6.4 资料完整度

资料完整度不落库，按五个等权分组实时计算，每组 `20%`：

1. 基本信息完整。
2. 至少一个有效 SKU，且有效 SKU 核心字段完整。
3. 每个有效 SKU 存在有效默认供应商报价。
4. 每个有效 SKU 的外箱尺寸、装箱数量、净重和毛重完整。
5. 商品主图和每个有效 SKU 的 SKU 图片完整。

详情页可展示各分组缺失项；列表只展示总百分比和“完整/待完善”状态。

## 7. API 设计

### 7.1 商品接口

保留现有资源路径并采用向后兼容的加字段方式：

- `GET /api/products`：继续支持 `keyword`、`categoryId`、`status`、`page`、`size`，响应增加商品总库存、总安全库存、默认供应商、默认售价和资料完整度。
- `GET /api/products/{id}`：响应增加 SKU 库存、安全库存、内盒包装字段、图片 URL、供应商报价、资料完整度、创建时间和更新时间。
- `POST /api/products`：创建商品、SKU 及其供应商报价。
- `PUT /api/products/{id}`：更新商品、SKU 及其供应商报价。

新增和编辑请求允许在每个 SKU 下提交可选的 `supplierQuotes`。商品、SKU、规格和报价在同一个数据库事务中保存；任一业务校验或数据库操作失败时整体回滚。

现有供应商报价独立接口继续保留，供后续单独采购维护使用。文件上传先通过现有文件接口完成，再把文件 ID 随商品请求提交；数据库事务不承诺回滚已经写入文件存储的文件。

### 7.2 分类树

商品页复用现有分类查询接口。前端根据 `parentId` 构建树；商品数量由后端按分类及其后代统计，避免前端遍历所有商品。商品页不调用分类新增、修改或删除接口。

### 7.3 首页聚合接口

新增 `GET /api/dashboard/overview`，支持 `period=week|month|year`，返回：

- `summary`：商品、SKU、供应商、库存风险、订单、销售额、未收金额和草稿订单统计。
- `salesTrend`：日期、销售额和订单数。
- `stockAlerts`：商品、SKU、当前库存、安全库存和缺口。
- `recentOrders`：订单号、客户、金额、状态和业务日期。

查询接口使用数据库聚合，不保存统计快照。某个数据源为空时返回零值和空数组；真实查询异常返回统一错误响应，不用演示数据替代。

## 8. 数据流与状态管理

### 8.1 列表

路由查询参数保存 `categoryId`、`keyword`、`page` 和 `size`，刷新页面后筛选状态仍可恢复。分类、关键词或每页数量变化时页码归一为第一页。请求返回顺序由后端固定，避免翻页时记录跳动。

### 8.2 详情和编辑

详情页按商品 ID 加载一次聚合数据。进入编辑时再次读取最新详情，避免从列表中的精简数据编辑。保存成功后跳转回详情并重新请求；保存失败保留所有输入和当前步骤。

### 8.3 图片上传

上传组件负责类型、大小、进度、失败重试、预览和删除。商品表单只保存文件 ID。图片 URL 仅用于展示，不作为可编辑字段提交。

### 8.4 未保存状态

只要表单相对初始快照有变化，路由离开和关闭页面时给出确认。SKU 和包装弹窗关闭时只检查弹窗内部变更；确认保存后再写入向导本地状态，最终提交时统一写入后端。

## 9. 校验与错误处理

- 后端继续承担唯一性、引用完整性、非负数、默认 SKU、默认报价和重量关系等最终校验。
- 前端提供相同规则的即时提示，但不替代后端校验。
- 商品货号、SKU 货号和非空条码保持唯一。
- SKU 安全库存、尺寸、重量、售价、成本和起订量不得为负；起订量必须大于零。
- 毛重存在且净重存在时，毛重不得小于净重。
- 每个商品必须至少有一个 SKU，且只能有一个默认 SKU。
- 每个 SKU 最多有一个启用的默认供应商报价。
- 接口校验错误映射到对应字段或步骤；未知错误显示页内反馈和重试入口。
- 列表、详情和首页使用骨架或局部加载，不以全屏遮罩阻断整个应用。
- 首页每个区块独立处理空数据和错误，单个统计区失败不使整个工作台空白。

## 10. 测试策略

### 10.1 前端

- 路由测试：列表、新增、详情、编辑和未保存离开保护。
- 服务测试：商品详情、聚合字段、首页响应和错误映射。
- 组件测试：分类树联动、货号搜索、分页、六步校验、SKU 编辑、包装模式切换、图片上传和提交载荷。
- 页面测试：只读详情分区、文字操作入口、空数据、加载和接口失败状态。
- 运行现有 Vitest 全量测试和生产构建。

### 10.2 后端

- Flyway 迁移测试：当前数据库版本可无损升级，历史 SKU 获得正确默认值。
- 领域与服务测试：新增字段校验、统一包装复制、逐 SKU 差异、报价默认规则和完整度计算。
- 仓储测试：商品列表聚合、分类后代筛选、库存汇总和趋势分组。
- 控制器测试：商品创建/更新/详情和首页聚合响应。
- 事务测试：SKU 或供应商报价保存失败时商品变更回滚。
- 运行 Maven 全量测试。

### 10.3 联调和视觉验收

- 启动数据库、后端和前端，使用真实接口完成新增商品、多 SKU、统一包装、逐 SKU 包装、编辑和详情查看。
- 验证分类树、货号/SKU 搜索、分页、刷新状态恢复和详情跳转。
- 在 `1440px`、`1280px` 和较窄桌面视口检查首页、列表、详情、向导和弹窗。
- 确认无文字裁切、输入框遮挡、表格列重叠、无效外围留白或弹窗底栏覆盖内容。
- 对照已确认 Figma 页面检查布局、间距、颜色、状态标签和组件一致性。

## 11. 实施顺序

实施计划按以下纵向切片展开，每个切片都包含测试：

1. 数据库迁移与商品领域字段扩展。
2. 商品保存事务、详情和列表聚合接口。
3. 首页聚合查询接口。
4. 全屏主框架与公共表单组件。
5. 新版工作台首页。
6. 商品分类树、列表和分页。
7. 商品只读详情页。
