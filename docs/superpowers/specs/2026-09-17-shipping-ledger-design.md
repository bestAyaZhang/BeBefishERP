# 发货管理第一版

> 历史设计记录：当前界面与交互以 [2026-09-18 Figma 设计说明](2026-09-18-shipping-figma-design.md) 和最终实现为准。

用户确认：独立发货台账，不关联库存，不选择 SKU，不扣减库存；备货内容使用自由文本。物流公司提供接口后支持一键下单。

## 已确认范围

- 菜单：发货管理 → 发货列表，沿用 ERP 页面、认证和权限体系。
- 每条记录包含发货日期、收件人姓名/电话/地址、物流公司、重量（kg，可空）、物流单号、平台、预计运费（元，可空）、备货内容、备注、状态、备货人和下单人。
- 日期、收件人和备货内容必填；其他资料可逐步补充。下单人默认当前用户显示名，支持录入实际业务下单人；审计操作人始终取登录身份。
- 状态人工选择：未完成、已完成、缺货、部分发货；不推断签收或库存状态。
- 新建、编辑、详情、分页、关键字/日期范围/状态/平台筛选；默认当天，并有全部未完成和全部记录快捷入口。
- 重量和预计运费非负；未知保留 null，不能显示成零。多行备货、备注原样保存。版本号避免多人编辑覆盖。
- 本期不增加拆包、发货明细、自动计费或删除功能。

## 物流接口核对

用户提供：https://itxuqiu.yuque.com/at96e5/qvahq8/vgxgly#XoqEO

2026-09-17 已通过浏览器读取，标题为《ANE-路由轨迹标准接口文档-新OPC》，章节为轨迹订阅、轨迹推送和轨迹查询。轨迹查询要求已有 ewbNo，不提供创建订单能力。

用户随后补充：https://itxuqiu.yuque.com/gzlcs4/uucisb/zulotg?singleDoc ，标题《ANE-电子面单取号接口文档》。已核对下单取号协议并据此实现。

详情内的一键下单展开安能表单，填写收件省市区与详细地址、重量、体积、件数、货物名称、包装、产品、送货方式、付款方式及物流备注。寄件人和账号在服务端环境变量配置；配置未完成时按钮禁用。

后端使用独立物流订单表及单号，先提交预约记录再请求安能。成功回填正式物流单号、重量、地址；人工发货状态保持原值。结果不明时禁止重发，仅明确的身份验证失败允许重试。持久保存测试环境标记；测试运单不回填真实物流字段，正式发货需新建记录。暂不提供物流订单修改/取消、打印、轨迹同步和自动报价。

## 实现边界

后端新增 shipping 包、shipment/shipment_logistics_order 表和 shipping:view/create/edit/order 权限。使用 MySQL 持久化、参数化查询、服务端校验和版本比较。超级管理员获得新权限，其他角色通过现有权限管理分配。物流接口必须同时具备查看与物流下单权限。

前端新增 shipping 功能目录，使用 HTTP 服务和开发用 Mock 服务。复用 AccessibleDialog 完成编辑和详情，按钮遵守查看/新增/编辑权限。服务不可用时显示错误和重试，不使用虚假成功。
