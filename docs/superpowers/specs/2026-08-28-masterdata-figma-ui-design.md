# BeBefish ERP 主数据模块 Figma UI 设计说明

日期：2026-08-28

## 1. 目标

为 BeBefish ERP 的主数据模块建立一套可复用、可扩展的桌面端 Figma UI 设计。设计保留现有业务结构和核心流程，但重新优化视觉层级、信息密度、筛选效率、表单录入体验和跨页面一致性。

本轮设计以内部运营人员的高频桌面操作为核心，不制作营销式页面，不追求装饰性表现。最终设计应能直接支持前端实现和后续模块扩展。

## 2. 已确认的设计决策

- 首批范围为完整主数据模块：商品、分类、客户、供应商、仓库。
- 以现有业务流程为基础进行视觉和交互优化，不做 1:1 复刻。
- 首批只设计 1440px 桌面端。
- 采用“设计系统优先”方式，先建立基础变量和组件，再组合业务页面。
- 主框架采用全屏通栏布局，两侧不保留外层空白。
- 左侧侧边栏固定宽度并贯穿完整视口高度，不使用悬浮卡片式侧边栏。
- 商品详情使用约 50% 视口宽度的右侧抽屉。

## 3. Figma 文件结构

Figma 文件包含以下页面：

1. `01 Foundations`
2. `02 Components`
3. `03 Master Data`

### 3.1 Foundations

包含颜色、字体、字号、行高、间距、圆角、边框和阴影变量。变量命名使用语义化结构，例如：

- `Color/Brand/Primary`
- `Color/Surface/Page`
- `Color/Surface/Panel`
- `Color/Text/Primary`
- `Color/Text/Secondary`
- `Color/Border/Default`
- `Color/Status/Success`
- `Space/8`、`Space/12`、`Space/16`、`Space/24`、`Space/32`
- `Radius/6`、`Radius/8`

### 3.2 Components

包含主数据页面会重复使用的组件及状态：

- 侧边栏导航项与分组导航
- 顶部工具栏与面包屑
- 主按钮、次按钮、危险按钮、图标按钮
- 文本输入框、数字输入框、搜索框、文本域
- 下拉框、下拉选项、日期选择入口
- 状态标签、业务标签、筛选标签
- 图片上传、上传中、上传失败、图片预览
- 数据表格表头、数据行、勾选行、悬停行
- 分页器和每页数量选择
- 页面标题区、筛选区、批量操作栏
- 右侧抽屉、确认弹窗、反馈提示
- 加载、空数据、错误、无搜索结果状态

所有可重复元素必须创建为组件或组件实例，不交付扁平化的一次性节点。

### 3.3 Master Data

业务画板统一以 `1440px` 宽桌面框架展示，共 12 个核心业务画板：

- 商品列表
- 商品详情抽屉
- 商品新增表单
- 商品编辑表单
- 分类列表
- 分类新增/编辑抽屉
- 客户列表
- 客户新增/编辑表单
- 供应商列表及新增/编辑抽屉
- 仓库列表及新增/编辑抽屉
- 公共状态展示板

## 4. 主框架布局

### 4.1 全屏结构

- 应用占满整个浏览器视口，不设置外层最大宽度容器。
- 页面不使用外围 `body` 留白或包裹式大卡片。
- 左侧侧边栏固定宽度 `244px`，紧贴屏幕左侧并贯穿完整高度。
- 顶部工具栏从侧边栏右侧开始，横向铺满剩余内容区。
- 主内容区占据剩余空间，内部水平内边距使用 `24px` 或 `32px`。
- 主内容采用 12 栏栅格，基础间距为 `24px`。
- 业务页面应充分使用横向空间，避免在宽屏中形成大面积无效留白。

### 4.2 侧边栏

- 使用白色或极浅色表面，与主内容通过细边框分隔。
- 顶部显示 BeBefish ERP 品牌标识和产品描述。
- 导航支持一级入口和可展开分组。
- 当前路由使用主色背景、左侧指示条和清晰文字强调。
- 底部固定显示当前登录用户和账号入口。

### 4.3 顶部工具栏

- 左侧为面包屑和当前页面名称。
- 右侧提供全局搜索、账户、设置和退出等工具入口。
- 高度保持紧凑，避免形成营销页面式大标题区域。

## 5. 视觉规范

### 5.1 色彩

- 品牌主色：`#536DFF`
- 页面背景：`#F6F7FB`
- 内容表面：`#FFFFFF`
- 主文字：`#25314D`
- 次文字：使用中性灰阶
- 边框：浅灰蓝中性色
- 成功、信息、警告、危险状态分别使用绿色、青色、橙色和红色

状态颜色只用于表达业务含义，不用作大面积装饰。页面不使用大面积渐变、彩色光斑或单一色调堆叠。

### 5.2 字体

- 中文优先使用 Figma 环境中可用的 `Noto Sans SC`。
- 英文和数字优先使用 `Inter`。
- 若 `Noto Sans SC` 不可用，则选择可用的中文无衬线字体，并在交付说明中记录替代字体。
- 页面标题、区块标题、字段标签、正文、辅助文字和表格数字分别建立文字样式。

### 5.3 圆角与阴影

- 卡片和主要面板圆角为 `8px`。
- 输入框、按钮、标签使用 `6px` 到 `8px` 圆角。
- 阴影保持轻量，仅用于抽屉、下拉浮层、弹窗和需要明确层级的悬浮面板。
- 普通页面区块优先使用边框和间距区分，不将每个区块都做成浮动卡片。

### 5.4 图标

- 图标采用 Lucide 风格。
- 工具类操作优先使用熟悉的图标按钮，并提供明确的按钮名称或提示。
- 不使用手绘替代图标或装饰性 SVG。

## 6. 页面结构与业务交互

### 6.1 列表页通用结构

列表页从上到下统一为：

1. 页面标题、说明和主操作按钮
2. 筛选区
3. 已选筛选条件或批量操作栏
4. 数据表格
5. 分页器和每页数量选择

筛选字段根据业务类型使用文本输入框或统一下拉组件。列表页应支持快速重置、回车搜索和明确的筛选结果反馈。

### 6.2 商品模块

- 商品列表包含货号、品牌、供应商、分类和状态筛选。
- 点击整行打开右侧商品详情抽屉。
- 详情抽屉宽度约为视口的 50%，支持较多商品字段和图片素材。
- 商品新增和编辑使用独立表单页。
- 表单按基础资料、规格包装、价格库存、渠道信息、图片素材分区。
- 产品图片、外箱图片和内盒包装图使用图片上传组件。
- 品牌、供应商、分类、渠道商、包装类型等使用统一下拉组件。

### 6.3 分类模块

- 分类列表包含名称、排序、状态、备注和操作列。
- 新增和编辑使用右侧抽屉。
- 抽屉聚焦分类名称、排序号和备注等少量字段。

### 6.4 客户模块

- 客户列表突出客户名称、联系人、电话、渠道、状态和欠款信息。
- 新增和编辑使用独立表单页。
- 表单按基础信息、联系方式、渠道与结算、地址与备注分区。

### 6.5 供应商模块

- 供应商列表突出名称、联系人、电话、主营分类、结算方式和状态。
- 新增和编辑使用右侧抽屉。
- 支持供应商状态、分类和关键词筛选。

### 6.6 仓库模块

- 仓库列表突出名称、编码、类型、负责人、地址、默认仓和状态。
- 新增和编辑使用右侧抽屉。
- 默认仓操作需要明确状态反馈。

## 7. 状态与错误处理

- 加载状态使用表格骨架或行级加载，不让页面整体跳动。
- 空数据状态提供清晰说明和主操作入口。
- 无搜索结果状态保留当前筛选条件，并提供清除筛选操作。
- 接口错误在页面内容区显示可重试提示，不使用阻断式全屏错误。
- 表单校验在字段附近展示，保存失败时保留已输入内容。
- 停用、删除等高风险操作使用确认弹窗，并说明影响范围。
- 图片上传包含空态、上传中、成功、失败和预览状态。

## 8. Figma 原型连接

首批交互原型连接以下主要流程：

- 商品列表 → 商品详情抽屉 → 编辑表单 → 保存 → 返回列表
- 商品列表 → 新增商品 → 保存 → 返回列表
- 分类列表 → 新增/编辑抽屉 → 保存 → 列表刷新
- 客户列表 → 新增/编辑表单 → 保存 → 返回列表
- 供应商列表 → 新增/编辑抽屉 → 保存 → 列表刷新
- 仓库列表 → 新增/编辑抽屉 → 保存 → 列表刷新

## 9. 验证要求

- 每个业务画板必须使用组件实例和设计变量。
- 所有画板必须验证无文字裁切、无元素重叠、无无效大面积留白。
- 表格、筛选区、抽屉和表单分别进行局部截图检查。
- 验证中文字体和英文数字字体符合设计规范。
- 检查主框架在 1440px 宽度下完整铺满，两侧无外层留白。
- 检查左侧侧边栏为通栏结构并贯穿完整画板高度。
- 检查商品详情抽屉约占 50% 视口宽度。
- 检查公共组件的默认、悬停、聚焦、禁用、错误状态是否齐全。

## 10. 本轮不包含

- 平板和移动端适配
- 工作台、库存、销售和财务模块的完整 Figma 页面
- 前端代码修改或视觉实现
- 后端接口和数据结构修改
- 完整品牌升级或营销视觉设计

## 11. 验收标准

本轮 Figma 设计在满足以下条件时视为完成：

- `Foundations`、`Components`、`Master Data` 三个页面结构完整。
- 主数据五个模块的核心页面和关键状态齐全。
- 设计系统变量、组件和业务画板之间存在清晰复用关系。
- 主框架采用全屏通栏布局，侧边栏无外围留白。
- 页面适合高频 ERP 操作，信息层级清晰，表格和筛选效率优先。
- 主要业务流程可以通过 Figma 原型进行点击演示。
- 所有关键画板均已通过截图检查并完成必要修正。
