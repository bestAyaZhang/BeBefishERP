# 仓库货堆缩放与删除设计

**日期：** 2026-10-02
**状态：** 交互方案已确认，待书面设计复核

## 目标与边界

仓库规划编辑者可在现有画布中拖动货堆的边缘或四角，放大、缩小货堆；也可删除选中的货堆。若该堆关联 SKU，删除前明确提示；确认后解除这些 SKU 与货堆的关联，将该堆的实际库存转回“待分配”。不删除商品档案，不减少仓库总库存。

本功能只改变货堆布局和库存的库位分配，不新增容量算法、库存调整单或商品删除能力。仓库库存查看模式维持只读。

## 现状与方案选择

- `WarehouseBlueprintScene.vue` 已有货堆移动预览、防重叠校验和 8 个仅作装饰的选中控制点。
- `WarehouseCanvasView.vue` 管理规划快照、撤销/重做、货堆集合与实际库存。
- 规划通过 `WarehouseLayoutControls.vue` 保存到 `WarehouseLayoutService`；实际分配保存在 `inventory_location_balance`。当前布局保存不会清理已删除货堆的分配，直接删除会留下孤立库位。
- `WarehouseInventoryLayoutAssembler` 用仓库权威库存减去已放置库存计算“待分配”；删除货堆的库位分配后，库存总量可保持不变。

采用“本地暂存删除，保存时原子提交”方案。另一方案是确认后立即调用独立删除接口，但这会绕开既有的未保存提示和保存前撤销；仅在前端先删分配再保存布局则可能发生半成功，均不采用。

## 画布交互

1. 仅在规划编辑的“货物”工具中，选中货堆后显示可操作的 8 个缩放控制点（四边中点、四角）。拖动货堆内部仍用于移动；控制点使用独立指针事件，不能触发移动。
2. 拖动期间实时显示尺寸预览并保持被操作货堆置顶；按当前缩放与视口换算指针位移，沿用现有网格吸附开关。最小宽高采用货堆创建时的一格；不能形成负尺寸，也不能超出仓库/画布可用边界。
3. 预览及放手时沿用现有货堆互斥和结构冲突判断。发生重叠或越界时，当前堆和冲突对象短暂红框提示，放手后恢复原尺寸；合法时一次性更新 `left/top/width/height`、派生米数和箱格行列数，并写入同一规划撤销快照。按 Escape 取消本次拖动。
4. 选中货堆后提供“删除货堆”操作；焦点不在输入框时也可用 Delete 键触发。普通货堆删除先确认。若有 SKU 关联，确认框展示货堆编号、关联 SKU 种类及实际个数，说明含 0 库存的 SKU 关联也会解除、正数库存转回“待分配”，仓库总库存不变。取消不修改画布。
5. 确认后货堆从当前规划草稿中移除，清空选中态，并进入现有未保存状态。保存前撤销可恢复货堆和其未提交的分配关系；保存成功后不承诺通过画布撤销恢复已解除的分配。
6. 实际库存加载失败时，不允许提交货堆删除确认，提示重试加载。无 `inventory:edit` 权限者不能确认删除已关联 SKU 的货堆；无关联货堆仍按 `warehouse:edit` 规划权限处理。

## 保存与后端一致性

布局保存请求在原有 `revision` 与 `document` 外，增加可选的 `releasedPileAllocations`，每项包括货堆 ID 和用户确认当时看到的全部 `{skuId, units}` 快照，含 0 个的关联。未删除货堆时不发送该字段。确认过但后来撤销删除的货堆不发送该项。服务端不信任客户端关于是否有库存的判断：它从旧布局和新布局计算真正被删除的货堆 ID。

`WarehouseLayoutService.save` 在单一事务内按既有锁顺序执行：

1. 检查 `warehouse:edit`、布局格式与修订号；锁仓库行、布局行，读取旧布局。
2. 比较旧新布局，找出被删除的货堆。对这些货堆，按 SKU 顺序锁权威 `inventory_balance` 和相应 `inventory_location_balance`，与确认快照逐个比较（SKU 集合及数量，包含零库存关联）。
3. 只要实际关联不等于用户确认的快照，即返回冲突，事务回滚，要求刷新库存后重新确认。存在关联而无对应确认项时拒绝保存；解除实际关联还要求 `inventory:edit`。没有关联的货堆可直接删除。
4. 删除已确认货堆的库位分配记录，按权威库存减去其余货堆已放置库存，更新对应 SKU 的 `UNALLOCATED` 库位记录；不改 `inventory_balance`，不写库存增减流水。
5. 写入新布局和新修订号，提交事务。任何一步失败时布局和库位分配同时回滚。

这个顺序与现有分配服务使用的“仓库 → 布局 → 库存余额 → 库位”锁顺序保持一致。仓库库存读取仍以权威余额为准。其他客户端即使绕过弹窗，也不能通过普通布局保存留下已分配货堆的孤立记录。

## 前端与 API 边界

- `WarehouseBlueprintScene` 只负责交互预览与发出 `resize-pallet`、`request-delete-pallet` 事件，不直接写库存。
- `WarehouseCanvasView` 负责更新草稿、撤销栈、确认框、已确认删除快照，以及保存成功后的库存刷新。未保存期间从画布移除的货堆仍以保存前的服务端库存为准；列表不得把它误显示为已转回“待分配”。
- `warehouseLayoutService` 的保存输入扩展为可选删除确认元数据；生产服务调用后端，演示模式在内存中执行同等的移除/转回语义。
- 若保存发生规划版本冲突、库存关联变化或权限不足，保持草稿与确认状态，显示可理解的错误；不能悄悄重试或自动覆盖他人的改动。成功后刷新实际库存和左侧货堆列表。

## 验证

- 单元/组件测试：8 个控制点的方向、缩放换算与网格吸附、最小尺寸、碰撞/边界回退、Escape 取消、移动与缩放互不触发、撤销/重做、删除确认与取消、空堆与有 SKU 堆、零库存关联、只读权限及库存加载失败。
- 后端集成测试：空堆删除；有正数及 0 库存关联的堆删除；SKU 数量转为待分配且仓库总库存不变；缺少确认元数据、快照过期、布局修订冲突、权限不足均不写入；与并发分配交错时不出现孤立分配或死锁。
- 端到端手测：不同缩放比例下拖动八个控制点；保存/刷新后尺寸保持；删除后左侧与详情展示的 SKU 和待分配数量一致。

## 不在本次范围

- 一次框选并批量缩放/删除多个货堆。
- 删除商品 SKU 档案、减少仓库总库存、自动转移到另一货堆。
- 保存成功后的跨事务“撤销删除”。
