# 电商内部 ERP 分阶段开发计划

## 1. 计划目标

本计划用于指导 ERP 从 0 到 1 分阶段开发、验收和上线。系统第一版按 20 人以内内部团队、单仓库、多平台数据导入、云服务器 Web 部署设计，采用 Java + Vue 3 + TypeScript + Tailwind CSS + MySQL 8 的模块化单体架构。

开发原则：

- 先跑通核心业务闭环，再补充看板和辅助模块。
- 每个阶段都必须能独立演示和验收。
- 库存、财务、单据状态必须后端事务保证一致性。
- 第一版不做复杂审批、完整会计、平台 API 直连、多仓库和飞书登录，只预留扩展。

## 2. 阶段总览

| 阶段 | 名称 | 主要目标 | 建议周期 |
| --- | --- | --- | --- |
| 阶段 0 | 项目准备与原型确认 | 明确 UI 原型、初始化项目、确认字段和流程 | 1 周 |
| 阶段 1 | 系统基础与登录权限 | 搭好前后端基础、手机号登录、角色权限 | 1-2 周 |
| 阶段 2 | 基础资料与产品体系 | 产品、货号、SKU、包装资料、物料、BOM | 2 周 |
| 阶段 3 | 库存与采购入库 | 库存余额、库存流水、采购入库、应付付款 | 2 周 |
| 阶段 4 | 组装入库与线下开单 | BOM 组装扣料入库、销售开单、出库、应收收款 | 2-3 周 |
| 阶段 5 | 财务经营流水与看板 | 应收应付、费用、经营总览、库存预警 | 2 周 |
| 阶段 6 | 平台导入与轻量考勤 | 平台 Excel/CSV 导入、考勤台账 | 2 周 |
| 阶段 7 | 联调验收与上线 | 全流程测试、数据初始化、部署备份、上线培训 | 1-2 周 |

第一版整体建议周期为 13-16 周。若开发团队只有 1 名全栈开发，周期需要相应拉长；若前后端、测试分工清晰，可按上表推进。

## 3. 阶段 0：项目准备与原型确认

### 目标

在正式编码前确认页面范围、字段口径、数据字典和上线环境，避免开发中频繁返工。

### 工作内容

- 根据现有需求文档整理页面清单和菜单结构。
- 输出核心页面低保真原型：登录、首页看板、产品、SKU、物料、BOM、采购单、组装单、销售单、库存流水、财务流水、平台导入、员工考勤。
- 确认产品资料字段：货号、SKU 编码、包装尺寸、体积、净重、毛重、克重、包装方式、包装图片、装箱数。
- 确认单据编号规则，例如采购单号、组装单号、销售单号。
- 确认云服务器、域名、短信服务商、文件存储方式。

### 交付物

- 页面清单和菜单结构。
- 核心页面原型。
- 字段确认表。
- 开发环境和测试环境说明。

### 验收标准

- 老板/管理员能确认第一版菜单范围。
- 开发团队能按页面清单拆前端任务。
- 后端能按字段确认表编写数据库迁移脚本。

## 4. 阶段 1：系统基础与登录权限

### 目标

搭建可运行的前后端项目基础，完成手机号登录和角色权限，为后续业务模块提供统一底座。

### 后端任务

- 初始化 Spring Boot 3 项目。
- 配置 MySQL、Redis、统一响应、统一异常、审计字段。
- 实现用户、员工、角色、权限、菜单基础表。
- 实现手机号 + 密码登录。
- 实现手机号 + 短信验证码登录。
- 实现退出登录和当前用户信息接口。
- 实现接口权限校验。
- 预留飞书登录字段，不开放飞书登录入口。

### 前端任务

- 初始化 Vue 3 + TypeScript + Vite + Tailwind CSS 项目。
- 搭建后台布局、菜单、路由守卫。
- 实现登录页：手机号密码登录、手机号验证码登录。
- 实现用户信息、角色菜单加载。
- 实现无权限、登录过期的统一处理。

### 核心接口

- `POST /api/auth/sms-code`
- `POST /api/auth/login/password`
- `POST /api/auth/login/sms`
- `POST /api/auth/logout`
- `GET /api/auth/me`

### 验收标准

- 管理员能用手机号 + 密码登录。
- 管理员能用手机号 + 验证码登录。
- 验证码 5 分钟有效、60 秒内不能重复发送、使用后失效。
- 不同角色登录后看到不同菜单。
- 禁用用户或禁用员工不能登录。
- 未登录访问业务接口返回未登录。

## 5. 阶段 2：基础资料与产品体系

### 目标

完成 ERP 的基础数据源，支撑后续采购、库存、组装、销售和看板。

### 后端任务

- 实现客户、供应商、仓库、员工基础资料。
- 实现产品/SPU，包含产品编码、货号、产品名称、分类、品牌、状态。
- 实现 SKU，包含 SKU 编码、条码、规格、售价、标准成本、包装资料。
- 实现 SKU 包装字段：包装长宽高、体积、净重、毛重、克重、包装方式、包装图片、装箱数。
- 实现物料，包含物料编码、条码、单位、标准成本、默认供应商。
- 实现 BOM 和 BOM 明细。
- 实现 SKU 标准成本按 BOM 自动计算。

### 前端任务

- 客户、供应商、员工、仓库列表和表单。
- 产品/SPU 列表、详情、编辑。
- SKU 列表、详情、编辑、包装图片上传或图片地址维护。
- 物料列表、详情、编辑。
- BOM 配置页面，支持选择成品 SKU 和物料用量。

### 验收标准

- 可创建产品并维护货号。
- 可通过货号查询产品。
- 可创建 SKU 并维护包装尺寸、体积、净重、毛重、克重、包装方式、包装图片、装箱数。
- 可创建物料并维护标准成本。
- 可配置 BOM。
- SKU 标准成本能按 BOM 用量自动计算。

## 6. 阶段 3：库存与采购入库

### 目标

建立库存余额和库存流水机制，完成采购入库和应付付款闭环。

### 后端任务

- 实现库存余额表和库存流水表。
- 实现库存服务，统一处理入库、出库、冲回和库存校验。
- 实现采购单和采购明细。
- 采购单确认后增加 SKU 或物料库存。
- 采购单确认后生成库存流水和应付记录。
- 实现付款记录，更新应付状态。
- 实现库存查询和库存流水查询。

### 前端任务

- 库存余额查询页面。
- 库存流水查询页面。
- 采购单列表、创建、编辑、详情、确认、作废。
- 付款记录页面。

### 验收标准

- 采购物料后物料库存增加。
- 采购成品 SKU 后成品库存增加。
- 采购确认生成库存流水。
- 采购确认生成应付记录。
- 付款后应付状态从未结清变为部分结清或已结清。
- 已确认采购单不能直接编辑，只能作废或按规则冲回。

## 7. 阶段 4：组装入库与线下开单

### 目标

跑通 MVP 最核心业务闭环：物料采购、组装成品、线下开单、扣库存、收款或欠款。

### 后端任务

- 实现组装入库单和组装物料明细。
- 组装确认时读取 BOM，检查物料库存。
- 组装确认后扣减物料库存，增加成品 SKU 库存。
- 组装单记录标准成本。
- 实现销售单和销售明细。
- 销售确认时检查 SKU 库存并扣减库存。
- 销售确认后生成库存流水、应收和收款记录。
- 实现销售单打印或导出数据接口。

### 前端任务

- 组装单列表、创建、详情、确认、作废。
- 组装单页面展示 BOM 物料需求和库存是否充足。
- 销售单列表、创建、详情、确认、作废。
- 销售开单支持客户、SKU、数量、单价、折扣、收款金额。
- 销售单打印或导出。

### 验收标准

- 物料库存不足时组装单不能确认。
- 组装确认后物料减少、成品增加。
- 销售库存不足时销售单不能确认。
- 销售确认后成品库存减少。
- 销售收款金额小于应收金额时生成欠款。
- 销售单进入经营看板统计来源。

## 8. 阶段 5：财务经营流水与经营看板

### 目标

形成老板日常查看经营情况的核心报表，不做完整会计总账。

### 后端任务

- 完善应收、应付、收款、付款、费用记录。
- 实现经营流水查询。
- 实现经营总览看板接口。
- 实现库存预警接口。
- 统计销售额、订单数、成本、费用、毛利、应收、应付。
- 保证销售单、采购单作废时财务记录按规则冲回。

### 前端任务

- 应收列表、应付列表、收付款记录。
- 费用登记页面。
- 经营总览看板。
- 库存预警看板。

### 验收标准

- 看板能按日期范围统计销售额、订单数、毛利。
- 看板能展示应收、应付、库存预警。
- 费用登记后能影响经营毛利统计。
- 作废销售单或采购单后，看板和应收应付同步变化。

## 9. 阶段 6：平台导入与轻量考勤

### 目标

通过 Excel/CSV 导入平台数据，补齐多平台经营汇总；同时完成轻量员工考勤台账。

### 后端任务

- 实现平台导入批次。
- 实现平台订单和平台订单明细落库。
- 支持 1688、淘宝/天猫、拼多多、抖音、京东的字段映射预留。
- 导入时记录成功行、失败行、失败原因。
- 支持平台 SKU 和内部 SKU 后续映射。
- 实现班次和考勤记录。
- 支持考勤手工录入或表格导入。

### 前端任务

- 平台导入页面。
- 导入批次列表和错误行查看。
- 平台销售汇总页面。
- 班次管理、考勤记录、考勤导入页面。

### 验收标准

- Excel/CSV 导入后显示成功行数和失败行数。
- 失败行能看到行号和错误原因。
- 平台订单能进入经营总览统计。
- 未映射 SKU 的平台订单只统计销售额和订单数，不统计 SKU 成本。
- 可录入或导入员工考勤记录。

## 10. 阶段 7：联调验收与上线

### 目标

完成端到端流程验收、初始化数据、生产部署、备份策略和内部培训。

### 工作内容

- 跑通完整流程：登录、建产品、建 SKU、建物料、配 BOM、采购入库、组装入库、销售开单、收款、看板统计。
- 准备初始角色、管理员、默认仓库、基础字典。
- 部署云服务器、Nginx、后端、前端、MySQL、Redis。
- 配置 HTTPS、数据库自动备份、文件目录备份。
- 整理上线检查清单和常见问题。
- 培训老板/管理员、仓库、销售、财务、采购、人事角色。

### 验收标准

- 主流程连续操作无阻断。
- 数据库备份任务可执行并能恢复验证。
- 不同角色账号能完成各自业务操作。
- 生产环境访问稳定。
- 第一版遗留项进入二期需求池。

## 11. 二期开发候选

以下能力不进入第一版主线，建议在第一版稳定运行后按价值排序：

- 飞书 OAuth 登录和飞书组织通讯录同步。
- 电商平台 API 授权和自动拉单。
- 多仓库、仓库调拨、库位管理。
- 扫码入库、扫码出库、扫码盘点。
- 退货、换货、退款、售后流程。
- 采购审批、付款审批、作废审批。
- 完整会计模块、会计凭证、总账、利润表。
- 工资核算、请假加班、打卡设备同步。
- 生产计划、工序、损耗、工时和制造费用分摊。

## 12. 风险与控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 产品字段反复变化 | 数据库和页面返工 | 阶段 0 完成字段确认表 |
| 库存与财务不一致 | 经营数据失真 | 所有确认动作统一事务，禁止直接改库存 |
| 导入模板不稳定 | 平台数据无法汇总 | 第一版先做通用模板和错误行反馈 |
| 权限边界不清 | 成本和财务数据泄露 | 菜单权限和接口权限同时校验 |
| 上线前无真实数据演练 | 生产使用阻塞 | 阶段 7 使用模拟真实数据跑全流程 |
