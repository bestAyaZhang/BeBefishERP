# 电商内部 ERP 开发文档

## 1. 开发目标

第一版开发以跑通核心经营闭环为目标：产品/SKU/物料/BOM、采购入库、组装入库、线下销售开单、库存流水、基础财务、平台导入、经营看板、角色权限、轻量考勤。

开发顺序必须围绕数据依赖展开，先基础资料和权限，再库存与单据，最后看板和导入。

## 2. 推荐迭代顺序

### 迭代 1：项目基础与权限

- 后端 Spring Boot 项目初始化。
- 前端 Vue 3 + TypeScript + Tailwind CSS 后台框架初始化。
- 手机号密码登录、手机号验证码登录、用户、角色、权限、菜单。
- 通用响应、异常处理、审计字段、日志。
- MySQL 初始化脚本和基础字典数据。

验收：

- 管理员可用手机号 + 密码登录。
- 管理员可用手机号 + 短信验证码登录。
- 不同角色看到不同菜单。
- 未登录访问 API 被拒绝。
- 禁用员工或禁用用户不能登录。

当前 `main` 已落地的阶段 1 基础：

- 后端已实现 `/api/auth` 下的发送验证码、密码登录、验证码登录、退出登录、当前用户接口。
- 后端已提供统一响应、认证异常和登录相关单元测试。
- 前端已实现登录页、认证接口封装、空响应兼容处理和登录页交互测试。
- 本地临时管理员只在 `local/test` Profile 初始化，短信登录已移除；登录页不展示开发凭据。
- 当前用户、短信验证码和访问令牌为内存实现，仅用于阶段 1 联调。

阶段 1 仍待完成：

- MySQL 用户、员工、角色、权限、菜单表落库。
- Redis 验证码、发送频率限制、令牌或短期会话存储。
- 后台主布局、路由守卫、登录过期统一处理。
- 角色权限管理页面、菜单加载和按钮级操作权限。
- 飞书 OAuth 登录不启用，只保留后续扩展边界和禁用态入口。

### 迭代 2：基础资料

- 员工、客户、供应商、仓库。
- 产品/SPU、货号、SKU、物料。
- BOM 维护和 SKU 标准成本计算。
- SKU 包装资料维护，包括包装尺寸、体积、净重、毛重、克重、包装方式、包装图片、装箱数。

验收：

- 可创建 SKU 和物料。
- 可维护产品货号，并通过货号查询产品。
- 可维护 SKU 包装资料，并上传或保存包装图片地址。
- 可配置 BOM。
- SKU 标准成本能按 BOM 自动计算。

### 迭代 3：库存与采购

- 库存余额表和库存流水表；当前已落地 V4 迁移，第一版先支持 SKU。
- 库存调整单已落地 V5 迁移，支持草稿、确认、作废。
- 采购单、采购明细、采购确认入库。
- 应付生成和付款记录。
- 库存查询和库存流水查询。

当前库存基础接口：

| 接口 | 说明 |
| --- | --- |
| `GET /api/inventory/balances` | 按仓库、货号、SKU 或商品关键字查询库存余额 |
| `GET /api/inventory/ledger` | 按仓库、SKU、方向和来源类型查询库存流水 |
| `GET /api/inventory/adjustments/{id}` | 查询库存调整单详情 |
| `POST /api/inventory/adjustments` | 创建库存调整草稿 |
| `PUT /api/inventory/adjustments/{id}` | 修改库存调整草稿 |
| `POST /api/inventory/adjustments/{id}/confirm` | 确认调整并写余额/流水 |
| `POST /api/inventory/adjustments/{id}/void` | 作废已确认调整并反向写入库存 |

库存服务实现要求：库存余额和流水必须在同一事务内更新；按 SKU ID 升序获取行锁；先校验全部明细再写入；确认后不允许直接改历史。

当前前端库存页面已接入上述接口，并通过基础资料接口加载启用仓库列表；余额、流水和调整页不写死仓库 ID。库存查询页为只读，调整页按“保存草稿 -> 确认调整”操作，确认后锁定表单。

验收：

- 采购物料后物料库存增加。
- 采购确认生成库存流水和应付。
- 付款后应付状态更新。

### 迭代 4：组装与销售

- 组装入库单。
- 组装确认扣物料、加成品。
- 销售单和销售明细。
- 销售确认扣库存、生成应收和收款记录。
- 销售单打印或导出。

验收：

- 组装单确认后物料减少、成品增加。
- 销售单确认后成品库存减少。
- 欠款生成应收，收款生成收款记录。

### 迭代 5：平台导入、看板、考勤

- 平台导入批次、导入模板、错误行记录。
- 平台销售数据存储和汇总。
- 经营总览看板。
- 班次、考勤记录、考勤导入。

验收：

- Excel/CSV 导入后能显示成功和失败行数。
- 看板展示销售额、订单数、毛利、库存预警、应收应付。
- 可录入或导入考勤记录。

## 3. 后端分层规范

建议每个业务模块采用以下结构：

```text
module/
  controller/     REST API
  service/        业务编排和事务
  repository/     数据访问
  entity/         数据库实体
  dto/            请求和响应对象
  mapper/         对象转换
  enums/          模块枚举
```

分层规则：

- Controller 只处理参数校验、权限、调用 Service。
- Service 负责业务规则、事务、跨模块协作。
- Repository/Mapper 只负责数据访问，不写业务判断。
- 跨模块调用优先通过 Service 接口，不直接访问其他模块表。
- 库存、财务、单据状态变更必须在 Service 层统一事务中完成。

## 4. REST API 规范

### 4.1 URL 规范

```text
POST   /api/auth/sms-code
POST   /api/auth/login/password
POST   /api/auth/login/sms
POST   /api/auth/logout
GET    /api/auth/me
GET    /api/products
POST   /api/products
GET    /api/products/{id}
PUT    /api/products/{id}
DELETE /api/products/{id}
GET    /api/sales-orders
POST   /api/sales-orders              # 创建销售草稿
GET    /api/sales-orders/{id}
PUT    /api/sales-orders/{id}         # 仅草稿
DELETE /api/sales-orders/{id}         # 仅草稿
POST   /api/sales-orders/{id}/confirm
POST   /api/sales-orders/{id}/void
```

资源使用复数名词，动作使用子路径。确认、作废、导入、导出属于业务动作，不用普通更新接口代替。

销售确认补充：确认会在同一事务中校验并扣减库存、写入 `sales` 库存流水；作废已确认销售单会恢复库存并写入 `sales_void` 反向流水。应收和收款记录待财务模块接入后补齐。

销售草稿阶段规则：

- `POST /api/sales-orders` 只保存草稿、金额计算结果和客户/仓库/SKU 展示快照，不扣库存、不写库存流水、不生成应收或收款记录。
- 草稿单号由后端按业务日期生成，格式为 `SOyyyyMMddNNNN`，同一日期从 `0001` 开始递增。
- 列表支持 `page`、`size`、`keyword`、`status`、`dateFrom`、`dateTo` 查询参数；当前前端已接入单号、客户和状态查询。
- 明细保存默认售价、实际售价、折扣、数量、金额、标准成本和产品/SKU 展示字段快照，避免历史草稿因基础资料修改而无法还原。
- 确认接口会在库存事务完成后返回已确认状态；作废接口要求填写作废原因，并在库存回滚成功后返回已作废状态。应收和收款记录待财务模块接入后补齐。

### 4.2 认证接口

| 接口 | 说明 | 关键请求字段 | 成功结果 |
| --- | --- | --- | --- |
| `POST /api/auth/login/password` | 手机号 + 密码登录 | `mobile`、`password` | 返回访问令牌、用户信息、角色、权限 |
| `GET /api/auth/feishu/authorize` | 发起飞书 OAuth | 无 | 重定向到飞书授权页 |
| `GET /api/auth/feishu/callback` | 飞书 OAuth 回调 | `code`、`state` | 重定向到前端一次性票据页 |
| `POST /api/auth/feishu/exchange` | 交换一次性票据 | `ticket` | 返回访问令牌、用户信息、角色、权限 |
| `POST /api/auth/logout` | 退出登录 | 请求头访问令牌 | 当前令牌失效 |
| `GET /api/auth/me` | 获取当前用户 | 请求头访问令牌 | 返回用户、员工、角色、权限、菜单 |

认证规则：

- 正式员工只使用本企业飞书 OAuth，临时员工只使用本地手机号和密码。
- 会话、OAuth state、一次性票据和登录审计持久化到 MySQL，令牌只保存 SHA-256 哈希。
- 飞书角色只映射到非敏感 ERP 角色；ERP 权限定义仍是唯一权限来源。
- 前端登录令牌当前保存在 `localStorage`，key 为 `bebefish_access_token`，后续如改为更安全方案需同步更新认证封装和文档。
- `local` Profile 可初始化本地临时管理员，凭据不在登录页展示；生产不得启用 `local/test` Profile。

## 5. 单据开发规则

所有业务单据遵循草稿、确认、作废状态。

创建草稿：

- 写单据主表和明细表。
- 不影响库存和财务。

确认单据：

- 校验状态必须为草稿。
- 校验明细完整性。
- 执行业务影响，例如库存和财务。
- 状态改为已确认。
- 写确认人和确认时间。

作废单据：

- 校验状态必须为已确认。
- 生成反向库存流水或反向财务记录。
- 状态改为已作废。
- 写作废人、作废时间和作废原因。

## 6. 库存服务规则

库存变动统一通过库存服务执行，禁止业务模块直接修改库存余额。

库存服务提供能力：

- 查询库存余额。
- 检查库存是否充足。
- 入库：增加库存并写入流水。
- 出库：检查库存、扣减库存并写入流水。
- 冲回：按原流水生成反向流水。

库存服务必须记录：

- 仓库。
- 库存对象类型和对象 ID。
- 变动方向。
- 变动前库存。
- 变动后库存。
- 来源单据类型和来源单据 ID。

## 7. 财务服务规则

财务服务统一处理应收、应付、收付款和费用。

- 销售单确认后生成应收。
- 采购单确认后生成应付。
- 收款记录关联应收，付款记录关联应付。
- 费用记录直接进入经营流水。
- 作废销售单或采购单时，关联应收应付必须作废或冲回。

第一版不生成会计凭证，不维护会计科目。

## 8. 导入开发规则

导入模块按批次处理。

导入接口流程：

1. 保存上传文件。
2. 创建导入批次，状态为 processing。
3. 解析文件头并匹配模板。
4. 逐行校验字段。
5. 成功数据写入业务表。
6. 失败行记录行号、原始值、错误原因。
7. 更新批次状态为 success、partial_failed 或 failed。

平台导入模板需要保留以下公共字段：

- 平台。
- 店铺。
- 外部订单号。
- 下单时间。
- 商品名称。
- 外部 SKU。
- 数量。
- 金额。
- 平台费用。
- 原始订单状态。

## 9. 看板计算规则

经营总览默认按日期范围筛选。

指标来源：

- 销售额：线下销售单 + 平台导入销售额。
- 订单数：线下销售单数量 + 平台订单数量。
- 成本：线下销售按销售单明细成本统计；平台订单成本在 SKU 映射后统计。
- 毛利：销售额 - 成本 - 平台费用 - 费用。
- 库存预警：库存数量低于 SKU 或物料预警值。
- 应收应付：未结清应收和未结清应付。

第一版允许平台导入订单未映射 SKU，此类订单只计入销售额和订单数，不计入 SKU 成本。

## 10. 测试要求

功能开发和问题修复必须先补充或更新测试，再实现业务代码。若暂时无法自动化，必须先写清楚可重复的手工验证步骤，并在后续迭代补自动化测试。

后端至少覆盖以下测试：

- BOM 成本计算。
- SKU 包装尺寸、体积、净重、毛重、克重、包装方式、包装图片、装箱数保存和查询。
- 手机号密码登录和手机号验证码登录。
- 验证码发送频率、过期和使用后失效。
- 禁用用户或禁用员工不能登录。
- 采购确认入库。
- 组装确认扣物料加成品。
- 销售确认扣库存并生成应收。
- 库存不足时阻止确认。
- 单据已确认后禁止直接编辑。
- 作废单据生成反向库存流水。
- 平台导入成功和失败行处理。

前端至少覆盖以下手工验收：

- 登录页密码登录、验证码登录、退出登录和未登录提示。
- 登录页黑白背景、动效面板无遮挡、模式切换位置、英文大写字段标签。
- 列表分页、筛选、排序。
- 新增、编辑、详情、确认、作废。
- 权限菜单显示和按钮禁用。
- 导入文件成功、部分失败、全部失败提示。
- 看板日期筛选和指标刷新。

## 11. 发布流程

1. 开发环境自测。
2. 测试环境部署。
3. 导入初始化数据。
4. 使用验收场景跑通主流程。
5. 备份数据库。
6. 生产环境发布。
7. 发布后检查登录、开单、库存、看板。

生产数据库变更必须通过迁移脚本执行，不允许手工改表后不留记录。
