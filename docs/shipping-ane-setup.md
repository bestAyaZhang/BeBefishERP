# 发货管理与安能电子面单

入口：发货管理 → 发货列表，地址 `/shipping/list`。

第一版使用文本备货清单，人工维护未完成、已完成、缺货、部分发货四种状态，不依赖商品、SKU、销售单或库存。运费预测为手工预计金额；留空表示尚未估计，0 表示预计免费。

## 启用台账

后端启动时由 Flyway 执行 V17（发货台账和权限）、V18（物流下单记录和权限）和 V19（店铺、多人备货、拆分地址及安能下单草稿）迁移。V12–V16 保留给已执行的仓库规划与库存迁移，避免与现有数据库的版本号冲突。真实数据库需要先备份并按项目部署流程启动后端。前端本地可使用 `VITE_DATA_SOURCE=auto`，测试和线上使用 `real`。

超级管理员自动获得新增权限；其他角色可在权限管理中分配 `shipping:view`、`shipping:create`、`shipping:edit`、`shipping:order`。已有登录会话如未显示新菜单，重新登录刷新权限。

后续扩展顺序建议：地址承运检查 → 电子面单取号 → 轨迹查询；按实际业务增加修改、取消以及轨迹订阅。普通网单用于需要网点接货流程的场景，接入前应确认账号开通范围和取号时机。台账的“已完成/未完成/缺货/部分发货”仍是人工备货、发货状态，与物流揽收、运输、签收状态分开维护。

文档中需注意的兼容性问题：

- 普通网单文档的第5节“订单查询”、第6节“运单查询”均已标记废弃；不能据此实现电子面单超时后的自动查单或重试，需安能提供当前有效的订单核查方案。
- 筛单文档展示的测试地址是 `/aneop/op/general/filter`，但超链接目标是 `/aneop/opwb/lb/queryOrn`，两者不一致；接入前需向安能确认有效地址。判断承运能力应结合 `siteNo`、`matchResult` 与 `matchMapType`，不能只看接口调用成功；超区应单独提示，盲区和无效地址不能当作正常匹配。
- 轨迹查询测试地址为 `https://traceopc.test.ane56.com/api/trace/query/traceQuery`；订阅测试地址为 `https://traceopc.test.ane56.com/api/trace/sub/subScribe`。订阅推送需要提供接收回调地址，并实现验签、重复推送去重及乱序处理。文档注明部分退回状态仅通过推送提供，单纯查询不等同于完整同步。
- 这四份文档未提供独立的下单前运费试算接口。已有运单的费用字段不能用作下单前报价；当前“运费预测”继续手工填写，自动计算需要另行取得报价接口或计费规则。

通过后端进程环境变量设置下列配置；`.env.example` 是模板，Spring Boot 不会自动读取根目录 `.env`。真实密钥不要提交 Git，也不要放入 `VITE_` 前端环境变量。

## 下单流程

新建或编辑发货单时，所有安能参数都位于当前表单内，不再打开独立物流页面。可在收件人卡片粘贴整段姓名、电话和地址，点击“智能识别”后，姓名、电话、省、市、区县和详细地址会同步到同一卡片下方；识别不完整时只覆盖成功识别的字段，已手填内容不会被空值清除。

“仅保存发货单”只校验台账必填项，安能草稿可暂不完整；“保存并一键下单”会先保存发货单，再校验和提交安能资料。新建发货单的发货日期由服务端取创建日，状态固定为“未完成”，下单人取当前登录人员，页面不要求重复录入。编辑时才显示并允许维护状态。

浏览器调用 `POST /api/shipments/{id}/logistics-order` 时只提交已保存发货单的 `version`。收件地址、货物、重量、体积、件数和物流选项全部由后端读取保存快照，浏览器不能在下单请求中覆盖这些资料。

安能要求重量至少1kg且最多两位小数、体积至少0.01m³、件数至少1。寄件人来自服务端配置。回单默认无回单，签收/到件/派件短信默认关闭。预计运费不会作为物流收费参数传给安能。

正式取号成功回填主运单号和安能物流，成功弹窗显示物流单号，并提供“返回发货列表”和“继续下单”。发货状态不自动改成已完成。已提交的物流订单会锁定平台、店铺、备货人、收件资料、运费预测和安能字段；备货清单、备注和发货状态仍可编辑。

订单的测试/正式环境会永久保存在数据库。测试运单仅显示在详情的测试订单区域，不回填台账的实际物流单号；即使后续切换正式配置，旧测试单仍保留测试标识。正式走货必须新建发货单，不能复用已提交测试订单的台账。

## 失败与重复提交

- 每张台账只有一条安能订单记录，平台订单号固定且不超过30字符。
- 数据库先锁定发货单并提交下单预约记录，再调用安能，避免长时间持有事务和重复发单。
- 成功、处理中、结果待核实的订单不会再次调用安能；可刷新已有结果。
- 仅文档明确的账号、摘要、时间戳验证失败允许修正配置后重试。其他失败（包括盲区匹配）、网络超时、响应解析错误都按结果待核实处理。
- 长时间处理中会显示待核实。请用详情里的安能订单号联系网点核查；本期没有自动重试、取消、修改物流订单或人工重置接口，避免不明状态重复下单。
- 下单确认结果与回填在同一事务；若本地回填失败，预约记录继续阻止重发，需运维核查数据库及网点结果。
- 如果“保存并一键下单”在保存后遇到安能错误，已保存的发货单不会回滚或重复创建；页面切换到该发货单的编辑地址并提示失败原因，可核对后重试。

## 验证与边界

本地测试使用受控 HTTP 模拟服务器校验请求、签名和响应解析，不会向安能提交真实订单。生产启用前仍需配置专用测试数据库跑迁移/读写联调，并使用安能测试账号进行一次取号验收。第一版备货清单是自由文本，不选择 SKU、不关联或抵扣库存；当前也不提供面单打印、轨迹同步、自动运费报价、物流取消和分批包裹管理。
